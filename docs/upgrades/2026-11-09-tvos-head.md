## Why

The template can now target Apple TV. New apps pick `tvos` like any other platform, and this note is how an existing app
gets the same head.

Read [tvos.md](https://github.com/MartinZikmund/uno-app-template/blob/main/docs/tvos.md) first. tvOS runs on the interpreter, has no share sheet, can't open links yet and has
no SQLite, so it isn't a free extra head for every app.

## Who is affected

Only apps that want to run on Apple TV. Skip this otherwise.

## Steps

**`mzuno-app upgrade --patch` won't add the head.** It generates the template with the platforms your app recorded, and
tvOS isn't one of them, so these steps are manual. It does deliver the shared build changes in step 5.

1. Install the workload. Restore evaluates every target framework, so everyone building the app needs it:

   ```bash
   dotnet workload install tvos
   ```

2. Add `net10.0-tvos;` to `TargetFrameworks` in `src/AppTemplate/AppTemplate.csproj` and
   `src/AppTemplate.Core/AppTemplate.Core.csproj`.

3. Copy [`src/AppTemplate/Platforms/tvOS/`](https://github.com/MartinZikmund/uno-app-template/tree/main/src/AppTemplate/Platforms/tvOS)
   into your head, and replace `App Template` in its `Info.plist` and `InfoPlist.strings` files with your app's name. Add
   [`docs/tvos.md`](https://github.com/MartinZikmund/uno-app-template/blob/main/docs/tvos.md) if you keep the template's docs.

4. In `src/AppTemplate/AppTemplate.csproj`, add the interpreter settings and use the same icon as iOS:

   ```xml
   <PropertyGroup Condition="'$(IsTvOS)' == 'true'">
       <MtouchUseLlvm>false</MtouchUseLlvm>
       <UseInterpreter>true</UseInterpreter>
       <MtouchInterpreter>all</MtouchInterpreter>
   </PropertyGroup>
   ```

   ```diff
   -<UnoIconBackgroundFile Condition="'$(IsIOS)' == 'true' or '$(IsAndroid)' == 'true'">Assets/Icons/icon.svg</UnoIconBackgroundFile>
   +<UnoIconBackgroundFile Condition="'$(IsIOS)' == 'true' or '$(IsTvOS)' == 'true' or '$(IsAndroid)' == 'true'">Assets/Icons/icon.svg</UnoIconBackgroundFile>
   ```

   If you reference `sqlite-net-e` and `SourceGear.sqlite3`, move them to their own group in both project files. Shared
   code that uses them must then be left out of this head or given another provider.

   ```xml
   <ItemGroup Condition="'$(IsTvOS)' != 'true'">
       <PackageReference Include="sqlite-net-e" />
       <PackageReference Include="SourceGear.sqlite3" />
   </ItemGroup>
   ```

5. Take the shared changes, if you have these files. Compare each with the template:
   [`src/MobileLabels.targets`](https://github.com/MartinZikmund/uno-app-template/blob/main/src/MobileLabels.targets) (Dev and worktree display names),
   [`src/DevAssets.Task.cs`](https://github.com/MartinZikmund/uno-app-template/blob/main/src/DevAssets.Task.cs) (the Dev badge inside the safe zone) and
   [`src/AppTemplate/Services/ShareService.cs`](https://github.com/MartinZikmund/uno-app-template/blob/main/src/AppTemplate/Services/ShareService.cs) (no share sheet).
   Anything your own code does with a share sheet needs the same `__TVOS__` guard.

6. With CI, add this to the `build` matrix in `.github/workflows/ci.yml`. It only compiles, so it runs on Windows:

   ```yaml
   - { name: tvos,    tfm: net10.0-tvos,              os: windows-2025 }
   ```

7. With the release workflows, copy [`_build-tvos.yml`](https://github.com/MartinZikmund/uno-app-template/blob/main/.github/workflows/_build-tvos.yml) into
   `.github/workflows/` and add a `build-tvos` job to `build-main.yml` and `release.yml`. In `release.yml`, also add
   `build-tvos` to the `tag` job's `needs`. The jobs to copy are in
   [`build-main.yml`](https://github.com/MartinZikmund/uno-app-template/blob/main/.github/workflows/build-main.yml) and [`release.yml`](https://github.com/MartinZikmund/uno-app-template/blob/main/.github/workflows/release.yml).

8. **A patch can't do this:** to sign builds, add the `APPLE_TVOS_PROVISIONING_PROFILE_BASE64` and
   `APPLE_TVOS_ADHOC_PROVISIONING_PROFILE_BASE64` secrets and the `APPLE_TVOS_PROVISIONING_PROFILE_NAME` variable. tvOS
   profiles are separate from iOS ones. Without them `_build-tvos.yml` builds for the simulator and runs a smoke test.

## Verify

```bash
dotnet build src/AppTemplate/AppTemplate.csproj -f net10.0-tvos
```

That compiles on Windows or a Mac. It says nothing about bundling or the native link, so also run the head in the Apple TV
simulator on a Mac, or push to `main` and check the `build-tvos` job. Then walk every page with the Siri Remote: tvOS input
is focus-driven, and the template's own pages haven't been reviewed for it.
