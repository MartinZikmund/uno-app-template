## Why

The template moved from Uno.Sdk 6.7 to 7. Uno 7 changes the Android entry points and a XAML namespace, stops needing the
`SkiaRenderer` feature, and no longer works with the published `CommunityToolkit.WinUI.*` packages, so the template builds
the pieces it uses from source.

`7.0.0-dev.179` is a dev build, and Uno 7 dev builds aren't binary compatible with each other. Pin the exact version.

## Who is affected

Every app still on Uno.Sdk 6. An app can stay on 6 and skip this for now, but later notes assume Uno 7.

## Steps

`mzuno-app upgrade --patch` delivers these, except where you've changed the same lines. Step 3 only applies if your app
uses the toolkit's controls or converters.

1. In `global.json`:

   ```diff
   -    "Uno.Sdk": "6.7.30",
   +    "Uno.Sdk": "7.0.0-dev.179",
   ```

2. In `src/Directory.Packages.props`, bump the toolkit and delete the `CommunityToolkit.WinUI.*` lines:

   ```diff
   -    <PackageVersion Include="MZikmund.Toolkit.WinUI" Version="0.1.21-dev.69" />
   +    <PackageVersion Include="MZikmund.Toolkit.WinUI" Version="1.0.0-dev.71" />
   -    <!-- Community Toolkit -->
   -    <PackageVersion Include="CommunityToolkit.WinUI.Controls.SettingsControls" Version="8.2.251219" />
   -    <PackageVersion Include="CommunityToolkit.WinUI.Controls.Primitives" Version="8.1.240916" />
   -    <PackageVersion Include="CommunityToolkit.WinUI.Converters" Version="8.2.251219" />
   -    <PackageVersion Include="CommunityToolkit.WinUI.Helpers" Version="8.1.240916" />
   ```

   Then remove these from `src/AppTemplate/AppTemplate.csproj` and `src/AppTemplate.Core/AppTemplate.Core.csproj`:

   ```xml
   <PackageReference Include="CommunityToolkit.WinUI.Controls.SettingsControls" />
   <PackageReference Include="CommunityToolkit.WinUI.Converters" />
   ```

3. Copy [`src/AppTemplate/ThirdParty/CommunityToolkit/`](https://github.com/MartinZikmund/uno-app-template/tree/main/src/AppTemplate/ThirdParty/CommunityToolkit) into your
   app head, and [`docs/community-toolkit-copy.md`](https://github.com/MartinZikmund/uno-app-template/blob/main/docs/community-toolkit-copy.md) if you keep the template's docs.
   The namespaces are unchanged, so code using these types stays as it is. In `src/AppTemplate/App.xaml`, merge the card's
   resources after `Colors.xaml`:

   ```xml
   <ResourceDictionary Source="/ThirdParty/CommunityToolkit/SettingsControls/SettingsCard/SettingsCard.xaml" />
   ```

   The folder's `README.md` lists exactly what the copy holds. If you use anything else from the toolkit, copy it from
   upstream tag `v8.2.251219` too.

4. In `src/Directory.Build.props`, remove `SkiaRenderer;` from `UnoFeatures`.

5. In `src/AppTemplate/AppTemplate.csproj`, delete this group if you have it. Uno.Sdk 7 makes these the defaults:

   ```xml
   <PropertyGroup>
       <SupportedOSPlatformVersion Condition="'$(IsIOS)' == 'true'">15.0</SupportedOSPlatformVersion>
       <SupportedOSPlatformVersion Condition="'$(IsAndroid)' == 'true'">24.0</SupportedOSPlatformVersion>
   </PropertyGroup>
   ```

6. In `src/AppTemplate/WindowShell.xaml`, and any other XAML using that namespace:

   ```diff
   -    xmlns:toolkit="using:Uno.UI.Toolkit"
   +    xmlns:toolkit="using:Uno.UI.Behaviors"
   ```

7. With the Android head, in `src/AppTemplate/Platforms/Android/Main.Android.cs`, add `using Uno.UI.Hosting;` and change
   the class:

   ```diff
   -public class Application : Microsoft.UI.Xaml.NativeApplication
   +public class Application : Uno.UI.Runtime.Android.NativeApplication
    {
        public Application(IntPtr javaReference, JniHandleOwnership transfer)
   -        : base(() => new App(), javaReference, transfer)
   +        : base(javaReference, transfer)
        {
        }
   +
   +    protected override UnoPlatformHost CreateHost() =>
   +        UnoPlatformHostBuilder.Create()
   +            .App(() => new App())
   +            .UseAndroid()
   +            .Build();
    }
   ```

   In `MainActivity.Android.cs`:

   ```diff
   -public class MainActivity : Microsoft.UI.Xaml.ApplicationActivity
   +public class MainActivity : Uno.UI.Runtime.Android.ApplicationActivity
   ```

8. In each test project on `MSTest.Sdk` that references your app's Core project, turn off a check that doesn't recognize
   those projects as tests:

   ```xml
   <UnoDisableUNOB0029Validation>true</UnoDisableUNOB0029Validation>
   ```

9. With the Windows head, also follow
   [the package size note](https://github.com/MartinZikmund/uno-app-template/blob/main/docs/upgrades/2026-11-09-windows-package-size.md). Its trimmer descriptor is what keeps
   a trimmed package from crashing at launch once the toolkit packages are gone, and its workflow step finds the
   Windows App Runtime in the layout WinAppSDK 2.x uses.

## Verify

```bash
git grep -n "CommunityToolkit.WinUI\." -- "*.csproj" "*.props"   # expect no matches
dotnet build src/AppTemplate/AppTemplate.csproj -f net10.0-desktop
dotnet test tests/AppTemplate.Core.Tests/AppTemplate.Core.Tests.csproj
```

Build the other heads you ship the same way, then open your settings page and check the cards still look right.
