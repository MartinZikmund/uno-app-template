## Why

The template now targets .NET 11. Every target framework moves from `net10.0-*` to `net11.0-*`, the SDK pin in
`global.json` moves to `11.0.100`, and Uno.Sdk moves from the `7.0.0-dev.179` dev build to the stable `7.0.22`, which is
the first Uno 7 release that knows about .NET 11 Windows packages.

## Who is affected

Every app still on .NET 10. An app can stay on .NET 10 for now, but later notes assume .NET 11, and their snippets and
paths will say `net11.0`.

## Steps

`mzuno-app upgrade --patch` delivers these, except where you've changed the same lines.

1. Install the .NET 11 SDK (11.0.100 or later), then restore the workloads for it. Workloads are per SDK band, so the
   ones you had for .NET 10 don't carry over:

   ```bash
   dotnet workload restore src/AppTemplate.slnx
   ```

2. In `global.json`:

   ```diff
   -    "version": "10.0.100",
   +    "version": "11.0.100",
   ```

   ```diff
   -    "Uno.Sdk": "7.0.0-dev.179",
   +    "Uno.Sdk": "7.0.22",
   ```

3. Replace `net10.0` with `net11.0` everywhere in the repository, outside `bin/` and `obj/`. That covers:

   - `TargetFrameworks` in `src/AppTemplate/AppTemplate.csproj` and `src/AppTemplate.Core/AppTemplate.Core.csproj`, and
     `TargetFramework` in every test project
   - the `TFM` values and publish paths in `.github/workflows/` and `.github/actions/prepare-wasm-assets/action.yml`
   - the publish directory in `wrangler.jsonc`, if you deploy to Cloudflare
   - `src/.vscode/`, `src/.run/AppTemplate.run.xml`, `src/AppTemplate/Properties/launchSettings.json` and
     `*.csproj.user`
   - docs and agent instructions (`AGENTS.md`, `.claude/`, `docs/`)

   For example, in `src/AppTemplate/AppTemplate.csproj`:

   ```diff
   -            net10.0-android;
   +            net11.0-android;
   ```

   Don't edit old notes under `docs/upgrades/`. They describe what was true when they were written.

4. In `.github/workflows/`, any `actions/setup-dotnet` step that pins a version rather than reading `global.json`:

   ```diff
   -          dotnet-version: 10.0.x
   +          dotnet-version: 11.0.x
   ```

5. With the Windows head, update the comment above `<WindowsAppSDKSelfContained>false</WindowsAppSDKSelfContained>` in
   `src/AppTemplate/AppTemplate.csproj` if you keep it. Uno.Sdk 7.0.22 still defaults that property to `true`, so the
   setting stays.

## Verify

```bash
git grep -n "net10\.0" -- ":!docs/upgrades"   # expect no matches
dotnet build src/AppTemplate/AppTemplate.csproj -f net11.0-desktop
dotnet test tests/AppTemplate.Core.Tests/AppTemplate.Core.Tests.csproj
```

Build the other heads you ship the same way. If a build fails with `NETSDK1147`, step 1's workload restore didn't run
against the .NET 11 SDK.
